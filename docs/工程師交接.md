> 程式：`KebbiMed`（Android、Kotlin、Jetpack Compose；minSdk 29、targetSdk 35），只跑在凱比 Nuwa AIR-H300（Android 15）上。

## 3. 凱比實測到的限制（AIR-H300）

- Android 15（API 35）、arm64-v8a、螢幕 1024×600 @160dpi，App 可用約 1024×574 dp（只有狀態列，沒有導覽列）。
- **沒有 Google Play 服務**：不能依賴 GMS、FCM。ML Kit 只能用 bundled 版（`com.google.mlkit:*`），不要直接依賴 `com.google.android.gms:play-services-mlkit-*`。
- **只有一顆前鏡頭，系統卻宣告了後鏡頭**：
  - `KebbiApp.getCameraXConfig()` 在沒有後鏡頭時限制成只用前鏡頭，不要拿掉。
  - CameraX 1.4 要先設 `cameraSelector`，再改其他設定。
  - 前鏡頭拍照一定要 `isReversedHorizontal = false`。
- **沒有 Android 語音引擎**：凱比上說話要用 Nuwa SDK（第 8 節）；`AndroidTtsVoice` 只給模擬器用。
- App 在最上層時，`FLAG_KEEP_SCREEN_ON` 讓凱比不睡、不換成凱比臉。
- **系統關掉了通知彈出**（第 7 節）。
- Nuwa SDK 的 `disablePowerKey()` 有效；`disableSystemAlertUI()` 只關凱比自己的提示視窗，擋不住 Android 的通知欄。
- 開機廣播送得到沒有 exported 的 `BootReceiver`。
- APK 只打包 `arm64-v8a`（凱比）和 `x86_64`（模擬器），因為 ML Kit 的中文 OCR 模型很大。

## 4. 架構

### 4.1 後端是排程的唯一來源
- 凱比**不能自己改提醒**。長者在凱比上加藥、停藥、改作息、清空藥單，都是送「變更申請」（R2）給後端。
- 後端收到就自動套用，發佈新的排程版本；凱比拉回新排程（B1）後才會生效。
- 後台照服員改藥、改作息，也是發佈新版本，凱比下次同步時拉回來，並告訴長者「站點照服員幫您更新了藥」。

### 4.2 計時在凱比本機
- 排程裡是今天往前 1 天、往後 7 天的「每一包藥」（occurrence），每一包有自己的 `occurrenceId`、時間、晚吃期限，都由後端算好。
- 凱比自己用 `AlarmManager` 準時叫醒，**斷網也會提醒**。
- 長者按了什麼、凱比判定了什麼，都先寫進本機的 outbox，有網路時再送（C1）。後端用 `eventId` 去重。

### 4.3 同步
- 所有連後端的程式都在 `sync/SyncManager.kt`，畫面和提醒引擎都不直接呼叫 API。
- `syncAll`：登記 → 查綁定 → 心跳 → 需要時拉排程、目錄 → 送 outbox。App 在前景每 1 分鐘一次，在背景由 `SyncWorker` 每 15 分鐘一次。
- 事件發生的當下會立刻試著送一次 outbox。
- 後端網址在 `app/build.gradle.kts` 開頭，打包成 `BuildConfig.API_BASE_URL`：debug 版是測試環境 `https://nt-test.foodplus.com.tw/api/v1/kebbi-med/`（`testApiUrl`），正式版是正式環境 `https://staging-healthplus.cip.gov.tw/api/v1/kebbi-med/`（`prodApiUrl`）。後端把凱比的 API 放在 `/api/v1/kebbi-med/` 底下，網址要填到這一層。
- debug 版的網址改成空字串就用 `sync/FakeBackend.kt`；正式版一定要接真的後端。假後端照 `:api` 的 `reference/` 計算，行為等於真後端的簡化版。

### 4.4 畫面由狀態決定
- `AppViewModel` 每秒看一次狀態：有藥在提醒中就顯示提醒畫面，有逾時沒看過的就顯示逾時畫面。
- 長者正在確認、送出申請時不會被打斷。
- 不要改回「收到事件就跳頁」：App 在背景或剛啟動時事件會被丟掉，這是舊版漏提醒的原因之一。

### 4.5 App 常駐前景
- App 取代凱比臉，`FLAG_KEEP_SCREEN_ON` 讓凱比不睡；在前景時用 Nuwa SDK 擋住電源鍵。
- App 不在前景時（重開機、按 Home、當掉），凱比臉會蓋在最上面，App 自己回不來（App 沒有設成 HOME）。要點通知，或用 RoFlow 打開。
- 後端在 App 連續 30 分鐘不在前景時通知照服員。

### 4.6 程式在哪裡

| 位置 | 內容 |
|---|---|
| `api/` | 純 Kotlin 模組：凱比會呼叫的 13 支 API（`KebbiApi`）、資料類別、錯誤碼、規則常數（`Rules`）、給後端參考的計算邏輯（`reference/`）、範例 JSON |
| `app/.../data/` | `Repo`（唯一的資料來源）、Room 資料庫（occurrence、outbox）、`DeviceStore`、`Clock` |

| `app/.../sync/` | `SyncManager`（只有這裡呼叫後端）、`SyncWorker`（背景心跳、補送）、`ApiFactory`、`FakeBackend`、`FakeCatalog`（假的藥品目錄） |

## 5. 後端 API

凱比會呼叫 13 支 API，定義在 `api/.../KebbiApi.kt`，完整說明在 `docs/後端接口文件.md` 第 4 節：

| 編號 | 用途 |
|---|---|
| A1–A5 | 登記、配對碼、換 token、查綁定狀態、心跳 |
| B1、B2 | 拉排程、回報已套用的版本 |
| C1–C3 | 服藥事件、查某天的狀態、操作紀錄 |
| R1、R2 | 上傳照片、變更申請 |
| E1 | 藥品目錄 |

- `deviceId` 是凱比登記（A1）時後端發的，不是 Android ID。照服員設定頁看得到「裝置編號」。
- 登記時送的 `hardwareId` 是 Android ID。Android 依 App 的簽章金鑰給不同的 Android ID：重裝 App 不會變，**換簽章金鑰就會變**（例如 debug 版換成正式版），後端會當成新的凱比，要重新配對。
- API 要改時：改 `:api` 的程式碼和範例 JSON，記在 `api/CHANGELOG.md`，並同步改 `docs/後端接口文件.md`。

### 5.1 服藥事件（C1）

| type | 何時 |
|---|---|
| `reminded` | 第一次提醒（畫面已顯示或已發通知、已說話） |
| `reminded_again` | 再提醒（T＋15，或「等一下」到期） |
| `snoozed` | 按「等一下」 |
| `taken` | 準時吃（T 前 30 分鐘到 T＋30） |
| `late_taken` | 逾時之後、晚吃期限之前才吃 |
| `overdue` | 凱比判定逾時（T＋30） |
| `missed` | 凱比判定漏服（過了晚吃期限） |
| `declined_late` | 過了晚吃期限才按「吃了」，凱比告訴長者這次不要補吃 |
| `reminder_failed` | 語音或畫面沒辦法呈現 |
| `not_reminded_device_off` | 凱比關機期間錯過，開機時已經過了晚吃期限 |

- `source`：`touch`（畫面）、`notification`（通知上的按鈕）、`system`（凱比依時間自己判定）、`voice`（之後做語音回答時用）。
- 操作紀錄（C3）目前有 `app.exit`、`notification.opened`、`upload.too_large`。

## 6. 服藥狀態與通知照服員

以這包藥的時間 T 為準（例：早餐後 08:00）。凱比的提醒流程（「等一下」的分鐘數、次數和 T＋30 是預設值，後台可以改，見下面 `reminderSettings`）：

| 時間 | 凱比會 |
|---|---|
| T 前 30 分鐘起 | 可以先按「吃了」，算準時 |
| T | 顯示這包藥並說話。App 不在前景時發通知，凱比照樣說話 |
| 按「等一下」 | 10 分鐘後再提醒，但不會晚過 T＋30；同一包最多按 2 次，剩不到 2 分鐘時也不顯示「等一下」 |
| T＋15 | 還沒吃，再提醒一次（畫面＋語音） |
| T＋30 | 記成逾時未服，說「現在吃也可以」。後端在 T＋32 發 LINE 給照服員 |
| 晚吃期限前 | 按「吃了」記成晚吃 |
| 過了晚吃期限 | 記成漏服，不能再補吃 |
| 首頁 20 秒沒動 | 進待機畫面 |

狀態：

| 狀態 | 條件 | 算不算有吃 |
|---|---|---|
| 準時 | T 前 30 分鐘到 T＋30 之間按「吃了」 | 算 |
| 逾時未服 | 到 T＋30 還沒吃，還可以吃 | 還沒定 |
| 晚吃 | 逾時之後、晚吃期限之前吃了 | 算（標示晚吃） |
| 漏服 | 過了晚吃期限還沒吃 | 不算 |
| 關機沒提醒到 | 凱比關機期間錯過 | 未知 |

- **晚吃期限**：這包裡每一種藥，到「下一次吃同一種藥」間隔的一半，取最早的那個，而且不早於 T＋30。
  - 例：一天兩次 08:00、18:30，早上那包最晚 13:15 吃；晚上那包最晚隔天 01:15。
  - 一天一次的藥是 12 小時後，會跨過半夜（狀態以每一包藥為單位，換日不會把它判成漏服）。
  - 每週一次的藥到當天 24:00。
  - 過了期限不讓吃，因為怕跟下一次太近，一次吃到兩份。
- 凱比和後端都會判定狀態：凱比判定給長者看，後端依事件重算，當作正式紀錄。兩邊用同一份 `Rules`。
- 「等一下」幾分鐘（預設 10）、最多按幾次（預設 2）、幾分鐘後逾時（預設 30，上面的 T＋30）由照服員在後台設定，放在排程的 `reminderSettings`：
  - App 存在 `DeviceData.reminderSettings`，載入、套用排程時帶到每一包的 `Occurrence.settings`，引擎直接用它。
  - 按過幾次存在資料庫 `occurrence.snoozeCount`（資料庫第 2 版，`MIGRATION_1_2`）。
- **通知照服員由後端負責，App 不直接發 LINE。** 後端用 LINE Messaging API（LINE Notify 已在 2025 年 3 月停止服務）：
  - 逾時未服：T＋32 發（多等 2 分鐘，讓晚一點送到的「吃了」趕上）。
  - 漏服、凱比離線（35 分鐘沒有心跳）、App 不在前景（30 分鐘）。
  - 詳細條件和建議文字見 `docs/後端接口文件.md` 第 7 節。

## 7. 提醒出現在哪裡

| App 的狀態 | 長者看到、聽到的 |
|---|---|
| 在前景 | 提醒畫面＋凱比說話；不發通知 |
| 不在前景（凱比臉蓋住） | 凱比照樣說話（念出藥名和劑量）＋發通知 |

- 每一包藥一則通知，狀態改變時更新同一則。通知上有「吃了」「等一下」；逾時後只有「吃了」（記成晚吃）。
- 通知設了 `setTimeoutAfter(晚吃期限)`，過了期限系統自動收掉。漏服不發通知。
- 不用全螢幕通知（`setFullScreenIntent`）：在凱比上 App 會被叫起來，10 毫秒後又被凱比臉蓋掉。
- **這台凱比關掉了通知彈出**（`heads_up_notifications_enabled = 0`），通知只會進通知欄，長者多半看不到，App 不在前景時實際上只剩語音。要不要打開還沒決定，**不要自己改凱比的系統設定**。

## 8. 凱比說話（Nuwa SDK）

- **直接用 Nuwa SDK 說話，不經過 RoFlow。** 原型時期以為凱比不能說話，那是因為凱比上沒有 Android 語音引擎；Nuwa SDK 實測可以說話。
- Nuwa SDK 的 aar 不放公開 repo：自己從 https://dss.nuwarobotics.com/ 下載（目前用 2.1.0.10），放進 `app/libs/`。程式直接編譯呼叫，**沒有 aar 編譯不過**。
- 整個 App 共用一個 `NuwaRobotAPI`。順序：`NuwaRobotAPI(context, IClientId(packageName))` → `registerRobotEventListener` → 收到 `onWikiServiceStart()` 後才能 `startTTS(text)`。之前要說的話會先存著，服務好了再說。
- `startTTS` 會排隊，不會自己打斷上一句，所以每次說話前先 `stopTTS()`。說完會收到 `onTTSComplete`。
- `disablePowerKey()` 有效；`disableSystemAlertUI()` 只關凱比自己的提示視窗，擋不住 Android 的通知欄。
- 有沒有安裝 `com.nuwarobotics.service` 決定是不是凱比：凱比上用 `NuwaVoice`，模擬器用 `AndroidTtsVoice`。
- 照服員設定頁可以看語音狀態，按「測試說話」確認。
- RoFlow 目前只規劃用來在 App 不在前景時打開 App，還沒設定。

## 9. 新增藥品

1. 設定 →「新增藥品」→ 相機。
   - 看到藥袋 QR Code 就自動拍。
   - 沒有 QR Code：6 秒後凱比說「我數到三就拍」，倒數三、二、一自動拍。長者也可以自己按「拍照」。
2. 辨識：醫院藥袋的 QR 格式 A（藥品說明）、格式 B（調劑資料，個資欄位當場丟掉）；沒有格式 A 就跑 OCR。
3. 比對後端的藥品目錄（學名、商品名、別名，正規化後完全相符，不做模糊比對）：
   - 對到 1 個：直接問用法。
   - 對到多個：在這幾個裡面選。
   - 對不到：依類別從目錄選。目錄裡也沒有：只上傳照片，告訴長者「這個藥目前不會提醒您」。
4. 問用法：一天幾次 → 飯前飯後 → 每次幾顆 → 吃幾天 → 確認。藥袋 QR 上寫的、或目錄預設的答案會標出來當建議。
5. 送出變更申請（R2），照片在背景上傳（R1），**上傳成功後刪掉凱比上的照片**。
6. 後端套用後，凱比說「已經幫您加上…以後每天…提醒您」。

- 個資：log 裡不能有 QR 原文、OCR 全文、藥名以外的處方內容（檢查方式見第 10 節的 adb 指令）。

## 10. 測試

- 單元測試：`ReminderEngineTest`（提醒規則和各種情境）、`AddWizardTest`、`SpeechTest`、`FakeBackendTest`、掃描相關的測試，以及 `:api` 的範例 JSON 和計算規則測試。
- 實機：裝 debug 版，在凱比上跑完整流程：配對、提醒、逾時、通知上的按鈕、加藥、停藥、改作息、斷網。
- 照服員設定頁要按住「照服員設定 ›」3 秒才進得去（`ui/Components.kt` 的 `CaregiverEntry`）。debug 版的照服員設定頁有：
  - 「快轉到下一次轉換前 10 秒」「回到真實時間」：只改 App 的時間。
  - 「假後端」：只有 debug 版的網址是空的（用假後端）時才有。配對畫面也會多一個「模擬後台綁定（測試）」，綁定假後端的「測試長者」。

    | 按鈕 | 做什麼 |
    |---|---|
    | 後台加藥／後台停藥 | 模擬照服員在後台改藥，凱比會說「站點照服員幫您更新了藥」 |
    | 2 分鐘後的測試提醒 | 加一個 2 分鐘後要吃的藥 |
    | 作息延後／提早 30 分 | 模擬後台改作息 |
    | 模擬斷網、下一次回 401、下一次回 500 | 測離線補送和錯誤處理 |
    | 停用／恢復凱比、解除綁定 | 測停用畫面和重新配對 |

  - 掃描畫面的「測試圖片」：用推到 App 資料夾的圖片代替拍照。
- 這些測試工具只在 debug 版有。接真的後端時，斷網、401、500 這類異常要換回假後端才能模擬。
- 掃藥袋的測試圖片：
  - 產生（只有假資料）：`./gradlew :app:testDebugUnitTest --tests "*TestBagImageGenerator"`，圖片在 `app/build/test-bags/`。
  - 推到 `/sdcard/Android/data/tw.kebbi.medreminder/files/test/`，在掃描畫面按「測試圖片」。
  - `tools/test-qr-cards.html` 是原型時期的卡片，QR 內容是 `KEBBI:M13`，現在的掃描**不認得**這個格式，只認醫院藥袋的格式。

### adb 常用指令

- 安裝、啟動：`adb install -r app/build/outputs/apk/debug/app-debug.apk`、`adb shell am start -n tw.kebbi.medreminder/.MainActivity`
- 在 Git Bash 下，adb 的裝置路徑（`/sdcard/...`、`/data/local/tmp/...`）要先 `export MSYS_NO_PATHCONV=1`。
- 只看這個 App 的 log：`adb logcat --pid=$(adb shell pidof -s tw.kebbi.medreminder)`

  - tag：`Sync`（同步）、`Voice`（語音、電源鍵）、`KebbiScan`（掃描）。

## 12. 建置、安裝與正式版

### 12.1 準備
- **Android Studio**：到 https://developer.android.com/studio 下載安裝，用預設值就好。第一次開啟會下載 Android SDK。
- **JDK 17 或 21**。Android Studio 內建的 JDK 就可以；在命令列建置時，`JAVA_HOME` 要指到 JDK 17 或 21（**Java 24 編譯不過**）。
- **Nuwa SDK**（凱比原廠 SDK）：授權不允許放進公開 repo，要自己到 https://dss.nuwarobotics.com/ 註冊下載 `.aar`（目前用 2.1.0.10），放進 `app/libs/`。**沒有 aar 會編譯失敗。**
- 打開專案：Android Studio → **Open** → 選 `KebbiMed` 資料夾（有 `settings.gradle.kts` 的那層），等「Gradle sync」跑完。跳出「升級 Android Gradle Plugin」時按「Don't remind me」，不要升級（版本集中在 `gradle/libs.versions.toml`）。

### 12.2 指令

```
./gradlew :app:assembleDebug                  # debug 版（接測試環境）
./gradlew :app:assembleRelease                # 正式版（接正式環境，要有 keystore/，見 12.5）
./gradlew :api:test :app:testDebugUnitTest    # 單元測試
./gradlew :app:lintDebug                      # lint
```

### 12.3 在模擬器試跑
1. **Device Manager** → **Create Virtual Device** → 選 **Tablet**（例如 Pixel Tablet）→ 系統映像選 API 35、x86_64。
2. 按 ▶（Run）。畫面是橫向。依序看到：啟動動畫 →「用藥提醒」→ **配對畫面**（配對碼和 QR Code）。
3. 照服員在後台網頁選長者、輸入配對碼完成綁定，App 就會進入首頁。藥單一開始是空的：在後台加藥並發布，1 分鐘內會拉回新排程。
- 模擬器上用 Android 內建語音說話；沒有藥袋可以拍，掃描畫面用「測試圖片」（第 10 節）。

### 12.4 裝到凱比上
1. 在凱比上打開**開發者選項**和 **USB 偵錯**：一般是「設定 → 關於 → 連點版本號碼 7 次」，再到「開發者選項」打開「USB 偵錯」。找不到入口的話，請洽 Nuwa（女媧創造）。
2. 用 USB 線接電腦和凱比，凱比上按「允許 USB 偵錯」。
3. 在 Android Studio 選凱比、按 ▶；或用命令列：

   ```
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   adb shell am start -n tw.kebbi.medreminder/.MainActivity
   ```

4. 第一次打開時允許通知，再完成配對。
- 換後端網址後要重新打包，裝之前先清除 App 資料（或解除安裝），讓凱比重新登記、重新配對。

### 12.5 正式版
- `./gradlew :app:assembleRelease`，APK 在 `app/build/outputs/apk/release/app-release.apk`。接正式環境，沒有 debug 版的測試工具，也不能用 `adb shell run-as` 讀 App 的資料。
- 每次發版，`app/build.gradle.kts` 的 `versionCode` 都要比上一版大（`versionName` 給人看），凱比才能覆蓋安裝；用 Nuwa 裝置管理更新也一樣。
- 沒有開混淆（`isMinifyEnabled = false`）：APK 大部分是 ML Kit 的 OCR 模型，混淆省不了多少，還要整個重測。

**正式簽章金鑰**
- Android 只能安裝有簽章的 APK；更新時，新版的簽章要跟裝置上那一版是**同一把金鑰**。
- 金鑰放在專案根目錄的 `keystore/`（`.gitignore` 已排除，**不上傳 git**）：
  - `kebbimed-release.jks`：金鑰。
  - `keystore.properties`：金鑰的位置、別名和密碼，`app/build.gradle.kts` 打包時讀它。
- 沒有 `keystore/` 也能打包 debug 版；正式版會變成沒簽章、裝不上去的 `app-release-unsigned.apk`。
- **這兩個檔案要另外備份**（例如公司的密碼管理工具）。遺失了就不能再發更新，每台凱比都要解除安裝、重裝、重新配對。
- 金鑰是這樣產生的（只做一次，**不要重做**）：

  ```
  keytool -genkeypair -keystore keystore/kebbimed-release.jks -storetype PKCS12 -alias kebbimed -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=KebbiMed Release, C=TW"
  ```

**從 debug 版換成正式版**
- debug 版用電腦上的 debug 金鑰簽章，跟正式版不同，**不能直接覆蓋安裝**：要先 `adb uninstall tw.kebbi.medreminder`，再 `adb install app/build/outputs/apk/release/app-release.apk`。
- 解除安裝會清掉凱比上的資料。Android 依簽章金鑰給 App 不同的 Android ID（App 用它當 `hardwareId`），所以後端會把它當成一台新的凱比，要重新配對。
