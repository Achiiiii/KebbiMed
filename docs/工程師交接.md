> 目的：把 App 從「原型後台（Firebase）」接到正式後台，並和 RoFlow（MQTT）串接。
> 程式：本專案 `KebbiMed`（Android、Kotlin、Jetpack Compose；minSdk 23、targetSdk 35）。

## 2. 架構：計時在凱比本機

- 用藥排程存在凱比，由 App 用 `AlarmManager.setAlarmClock` 準時叫醒，**斷網也會提醒**。
- 後台負責：存資料、讓照服員改藥單/作息、接收服藥事件、通知照服員與家屬。
- 換後台時，**只需要改 `sync/CloudSync.kt`**（它是唯一碰後台的檔案）；畫面和提醒邏輯不用動。

## 3. 後台要提供的介面（換成正式後台時）

App 目前對 Firestore 做的事，對應到正式後台需要這些 API：

| # | 用途 | 目前 Firestore 做法 | 正式後台建議 |
|---|---|---|---|
| 1 | 凱比開機：查這台凱比照顧哪位長者 | 讀 `robots/{deviceId}` 的 `elderId` | `GET /robots/{deviceId}` → `{elderId, elderName, stationId}` |
| 2 | 回報凱比在線 | 寫 `robots/{deviceId}.lastSeen` | `POST /robots/{deviceId}/heartbeat` |
| 3 | 上傳長者今天狀態 | 寫 `elders/{elderId}`（meds、schedule、today） | `PUT /elders/{elderId}/state` |
| 4 | 上傳事件 | 新增 `elders/{elderId}/events` | `POST /elders/{elderId}/events` |
| 5 | 照服員改藥／作息 → 凱比更新 | 監聽 `elders/{elderId}`，`updatedBy=="caregiver"` 且 `configUpdatedAt` 較新就套用 | 推播（MQTT/WebSocket/FCM）或凱比每幾分鐘 `GET /elders/{elderId}/config` |

**`deviceId`**：Android ID（凱比「設定 → 照服員設定」畫面上有顯示）。

### 資料格式

```json
// 長者設定（後台 → 凱比）
{ "elderId": "KB-0013", "name": "林阿公", "stationId": "德高",
  "meds": ["M13", "M18", "M07"],
  "schedule": { "breakfast": "08:00", "lunch": "12:30", "dinner": "18:30", "sleep": "22:00" },
  "configUpdatedAt": 1763532000000, "updatedBy": "caregiver" }

// 今天狀態（凱比 → 後台）
{ "today": { "date": "2026-11-19", "taken": 1, "total": 3,
    "slots": { "早餐後": { "time": "08:00", "status": "taken", "takenAt": "08:03:12", "meds": ["M13","M07"] } } } }

// 事件（凱比 → 後台）
{ "type": "dose.taken", "text": "早餐後 吃了", "slot": "早餐後", "deviceTime": 1763510592000, "source": "kebbi" }
```

藥品代號 M01–M41 對應「凱比用藥資料庫」（`data/MedDb.kt`）。後台的藥品清單要用同一套代號。

### 事件種類

| type | 何時 | 後台要做的事 |
|---|---|---|
| `reminder.fire` | 到吃藥時間 | 記錄 |
| `reminder.snooze` | 長者按「等一下」（10 分鐘後再提醒） | 記錄 |
| `reminder.repeat` | 過 15 分鐘還沒吃，再提醒 | 記錄 |
| `dose.taken` | 長者按「吃了」 | 記錄服藥紀錄 |
| `dose.missed` | 過 30 分鐘沒吃 | 記錄漏吃 |
| `caregiver.notify` | 漏吃時 | **通知照服員與家屬（後台、LINE 拉娃 APP）** |
| `med.add` / `med.remove` | 長者在凱比新增／刪除藥（`needCaregiverConfirm: true`） | 放進後台「待確認的藥」 |
| `schedule.update` | 改吃飯、睡覺時間 | 更新作息，通知照服員 |
| `setup.done` | 站點設定完成 | 記錄 |
| `day.rollover` / `day.complete` | 換日／當天全部吃完 | 統計用 |

提醒的時間參數在 `engine/ReminderEngine.kt` 的 `Rules`（15 分、30 分、10 分）。

## 4. RoFlow 串接（MQTT）—— 必做、優先

**2026/11/20 決定：凱比說話改由 RoFlow 負責。** 在凱比上實測時，App 用 Android 文字轉語音叫凱比說話，系統語音引擎一直沒有回應（狀態停在「語音啟動中…」）。手機上可以正常說話。所以凱比開口一定要走 RoFlow，MQTT 不再是選配。

分工：App 負責計時、畫面、通知和服藥紀錄；時間到由 App 發 MQTT 給 RoFlow，RoFlow 讓凱比說話、換表情、做動作，長者回答後 RoFlow 回報給 App。

已知（RoFlow MQTT 模組）：
- 可「發送訊息」與「接收訊息」；伺服器可選 **Nuwa Server-01** 或「新增伺服器」。
- 使用 Nuwa 伺服器時，Topic 必須以帳號前綴開頭：`fff669e5/`；英文大小寫有別；不可用 `$ # + *` 和空格。
- 訊息內容為文字。

建議 Topic 與內容（逗號分隔純文字，方便 RoFlow 處理）：

```
App → RoFlow   fff669e5/KB-0013/reminder   早餐後,08:00,利尿劑、降血糖藥      （type 另可用 /repeat、/missed）
RoFlow → App   fff669e5/KB-0013/reply      吃了,早餐後   或   等一下,早餐後
```

待 Nuwa 回覆：
1. Nuwa Server-01 能否讓外部 App 連線？位址、連接埠、TLS/WebSocket、帳號密碼。
2. 「接收訊息」能否當作流程的啟動條件，還是要流程先執行並停在該步驟等待？
3. 收到的文字能否存成變數讓凱比念出來？
4. RoFlow 流程與本 App 同時在凱比上，誰在前景？

實作建議：新增 `sync/MqttBridge.kt`（Eclipse Paho `org.eclipse.paho.client.mqttv3` 或 HiveMQ MQTT Client），
在 `data/Repo.tick()` 裡（和 `Notifier.onEvents` 同一處）收到 `EngineEvent.Fire/Repeat/Missed` 時發佈（不要放在畫面層，畫面不在前景時事件不會經過那裡），訂閱 reply 後呼叫 `vm.take(slot)` / `vm.snooze(slot)`。
斷線時保留 App 自己的提醒畫面當備案。

## 通知（2026/11/20 修正）
- 所有提醒事件（時間到、再提醒、漏吃）一律由 `Repo.tick()` 交給 `engine/Notifier.kt` 發系統通知，不管是鬧鐘、App 計時還是開機觸發。
  - 舊版只在 AlarmReceiver 發通知，事件常被 App 計時或 Application.onCreate 先吃掉，所以只看得到「沒吃到」。
- 每個時段一個通知編號，同一包藥的狀態會更新同一則；按「吃了」或補吃後自動收掉。
- App 在最前面（onResume）時不發通知，由畫面和語音提醒；螢幕關掉或在背景時才發。
- 通知文字含藥名：「早餐後 08:15 的降血壓藥該吃了」。

## 漏服通知：三個地方都會跳（2026/11/20 確認）
漏服的定義：時間到 30 分鐘還沒按「吃了」。這時三個地方都要通知：

| 誰 | 怎麼通知 | 誰負責 |
|---|---|---|
| 機器人本身 | App 切到「沒吃到」畫面＋語音；App 不在前景或螢幕關著時，跳系統通知 | App（已完成） |
| 長者手機（如果有） | 拉娃 LINE 機器人推播 | 後台＋拉娃機器人 |
| 站點照服員 | 拉娃 LINE 機器人推播 | 後台＋拉娃機器人 |

App 不直接發 LINE，只把事件送到後台；後台再交給拉娃 LINE 機器人推播給長者手機和照服員。

### App 送出的事件
App 目前寫入 Firestore 的 `elders/{elderId}/events`；換成正式資料庫後，請改成你們 API 的欄位。
- `dose.missed`：漏服。內容有時段（slot）、表定時間、藥名清單、是否已提醒過。
- `caregiver.notify`：同一時間送出，等級 warning。文字範例：「林阿公 早餐後 08:00 的利尿劑、降血糖藥沒吃」。
- `dose.late_taken`：長者事後補吃。可以拿來發「已補吃」的後續通知。

### 建議的 LINE 推播文字
> 林阿公 早餐後 08:00 的利尿劑、降血糖藥沒有吃到，請關心一下。

### 待確認
1. LINE 帳號綁定：每位長者本人（有手機的話）和負責的照服員，各自的 LINE 帳號在後台哪裡維護？長者沒有手機時，只發給照服員。
2. 發送時機：漏服當下立即發，還是彙整後再發？
3. 第 15 分鐘的「再提醒」要不要也通知？
4. 長者補吃（`dose.late_taken`）後，要不要再發一則「已補吃」？
5. 斷網補傳：事件的發生時間可能比後台收到的時間早。同一事件要能去重複，不能發兩次 LINE。


## 凱比原廠語音（Nuwa SDK）——放檔案就能用（2026/11/20）
- App 已寫好 `robot/RobotVoice.kt` 的 `NuwaVoice`，用反射呼叫 Nuwa SDK，沒有 SDK 也能編譯。
- 只要把 Nuwa SDK 的 `.aar` 放進 `app/libs/`，再重新打包，App 啟動時就會自動改用凱比原本的聲音（`KebbiApp.kt` 會自動判斷）。
- SDK 下載：Nuwa 開發者網站 https://dss.nuwarobotics.com/ （需註冊登入）。官方範例：github.com/nuwarobotics/NuwaSDKExample（TTS 範例在 voice/TTSActivity.java）。
- 呼叫順序：`IClientId(packageName)` → `NuwaRobotAPI(context, clientId)` → `registerRobotEventListener` → 收到 `onWikiServiceStart()` 後 → `startTTS(text)`。
- 可以在「照服員設定」頁看語音狀態，並用「測試說話」按鈕確認。
- 如果 SDK 可以用，凱比說話就不一定要等 RoFlow。RoFlow 仍可負責比較複雜的對話與動作。

## 新增藥品：不用按，自動掃描／拍照（2026/11/20）
長者一手拿藥袋，另一手不方便按確認，所以掃描改成全自動：
1. 相機畫面放大（1220×600），對準框也加大。
2. **看到 QR Code**：直接把藥加進藥單（`med.add`，`needCaregiverConfirm: true`），不用再按「對」。下一頁會顯示加了什麼藥；如果掃錯，可以按「不對，拿掉這個藥」（`med.remove`，`reason: scan_mistake`）。
3. **5 秒內看不到 QR Code**：自動拍下藥袋（藥名那面）。
   - 照片存在機器的 `files/med_photos/yyyyMMdd_HHmmss.jpg`。
   - 同時送出事件 `med.photo`（含檔名），請照服員在後台看照片、補登這包藥。
4. 右上角有「改用選的」和「返回」，給照服員手動處理。

**後台要做**：把 `med_photos` 的照片上傳到後台（目前只存在機器上），並在後台「待確認的藥」列表顯示照片，讓照服員選藥補登。


## 服藥狀態的定義（2026/11/20 更新，取代前面「30 分鐘＝漏服」的說法）
以時段時間 T 為準（例：早餐後 08:00）。

| 狀態 | 條件 | 事件 | 算不算有吃 |
|---|---|---|---|
| 準時 | T＋30 分鐘內按「吃了」 | `dose.taken` | 算 |
| 逾時未服 | 到 T＋30 分鐘還沒吃。通知照服員，但還可以吃 | `dose.overdue` ＋ `caregiver.notify`（kind: overdue） | 還沒定 |
| 晚吃 | 逾時未服之後、在晚吃期限前吃了 | `dose.late_taken` ＋ `caregiver.notify`（kind: late_taken, info） | 算（標示晚吃） |
| 漏服 | 過了晚吃期限還沒吃；或換日時還是逾時未服 | `dose.missed` ＋ `caregiver.notify`（kind: missed） | 不算 |

- **晚吃期限**：這個時段每一種藥，到「下一次吃同一種藥」間隔的一半，取最早的那個。
  - 例：利尿劑 08:00、18:30 吃，間隔 10.5 小時，所以早上那包最晚 13:15 吃。
  - 過了期限就不讓吃，因為怕跟下一次太近，一次吃到兩份。
  - 每週一次的藥不限期限，到當天結束。
- **程式位置**：
  - `ReminderEngine.lateCutoffMin()`：算晚吃期限。
  - `tick()`：到期限時把狀態標成 `lapsed = true`，並送出 `EngineEvent.Lapsed`。
  - `SlotState.note`：晚吃時記成 `"晚吃"`。
- **App 顯示**：
  - 逾時未服：黃色「還沒吃・點我」，點了可以直接吃。
  - 晚吃：「晚吃 ✓」。
  - 漏服：紅色「漏服」。
- **拉娃 LINE 推播建議**：
  - 逾時未服（`kind: overdue`）：推播給長者手機和照服員，請他們關心。
  - 晚吃（`kind: late_taken`）：發一則「已經晚吃了」，讓照服員知道不用再追。
  - 漏服（`kind: missed`）：留在服藥紀錄裡，要不要再推播給照服員，由後台決定。
- **服藥率**：分子是準時＋晚吃，分母是今天有藥的時段數。後台可以另外統計晚吃的比例。
